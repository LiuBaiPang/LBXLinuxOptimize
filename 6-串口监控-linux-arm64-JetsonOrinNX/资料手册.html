0. 快速上手:30 秒看懂怎么接飞控

你的飞控现在已经能用了! 探测发现一台 Auterion PX4 FMU v6C 正插在 USB 上, 对应 /dev/ttyACM0 —— 打开《串口监控工具》→「飞控 MAVLink」页 → 端口选 ttyACM0、波特率 115200 → 连接,就能看到心跳、姿态、电量等实时遥测。 USB 直连不需要任何接线,是调试期最安全的方式。

想把飞控装到机上、摆脱 USB 线,用 40-pin 排针的 UART(脚 8 发送 / 脚 10 接收 / 脚 6 共地):

Jetson 40-pin接飞控 TELEM 口(Pixhawk 标准)作用
脚 8 UART1_TX→RXJetson 发数据给飞控
脚 10 UART1_RX←TX飞控发数据给 Jetson
脚 6 GND—GND共地,必须接
不接电源脚5V/VCC除非你明确要用一路给对方供电
⚠ 40-pin 的串口出厂被系统占用为内核控制台 + 登录终端, 接飞控前必须先"释放":在工具的「资料」页点【释放40-pin串口】(输一次密码,重启生效)。 详见 第 3 节。

读图说明:

① 排针两排,左列 = 奇数脚(1,3,5…39),右列 = 偶数脚(2,4,6…40),引脚 1 在顶部(板上通常有白三角/丝印"1")。

② 所有信号都是 3.3V 电平——接 5V 电平信号会烧 SoC!反过来给飞控的 TELEM 口(也是 3.3V)是安全的。

③ 名字带 * 的脚(UART1_RTS/CTS、SPI1_CS0/CS1、SPI0_CS0/CS1)经过 TXB0108 电平转换器,驱动能力很弱(±20µA 级),适合接双向外设,不能直接灌负载。

④ 电源脚能力:每个电源引脚最大 1A(规格书 Note 1)。

⑤ CAN 不在 40-pin 上——载板有一个独立的 4-pin CAN 座(默认未启用,需要在设备树里开启 can0/can1 才会出现接口)。

3. UART1 专题:40-pin 串口(/dev/ttyAMA0)

① 针脚定义

40-pin 脚位信号方向(Jetson 视角)说明
8UART1_TXD输出Jetson 发送 → 接对方 RX
10UART1_RXD输入Jetson 接收 ← 接对方 TX
6 或 14 或 9GND—共地(任选一个,建议 6)
11UART1_RTS输出硬件流控,一般不用
36UART1_CTS输入硬件流控,一般不用

② 一般用法(重要:先释放再使用!)

出厂时这个口被系统这样占用:

/boot/extlinux/extlinux.conf → ... console=ttyAMA0,115200 ...   ← 内核日志打到脚8
systemctl status serial-getty@ttyAMA0                            ← 登录终端占用整个口

后果:飞控数据里会混进内核日志和 jetson login: 提示,普通用户还只有只写权限。 《串口监控工具》→「资料」页 →【释放40-pin串口】一键完成(等价于手工做下面三件事):

# 1. 停用串口登录终端(立即生效)
sudo systemctl disable --now serial-getty@ttyAMA0

# 2. 从启动参数去掉 console=ttyAMA0(需重启生效; 先备份!)
sudo cp /boot/extlinux/extlinux.conf /boot/extlinux/extlinux.conf.bak
sudo sed -i 's/ console=ttyAMA0,115200//' /boot/extlinux/extlinux.conf

# 3. 设备放权给 dialout 组(免 sudo 读写)
echo 'KERNEL=="ttyAMA0", GROUP="dialout", MODE="0660"' | \
  sudo tee /etc/udev/rules.d/99-aaafix-uart.rules

# 4. 重启
sudo reboot

释放完以后,正常使用就三步:

# 看这个口有没有数据流进来(波特率要和对方一致)
stty -F /dev/ttyAMA0 115200 raw -echo
xxd /dev/ttyAMA0          # Ctrl+C 退出

# 发一句话出去
echo -n "hello" > /dev/ttyAMA0
💡 验证接线是否正确的绝招——回环测试: 断电状态下用杜邦线把脚 8 和脚 10 短接, 然后在工具「串口终端」页打开 ttyAMA0,随便打字——能回显自己发的字 = 板上 TX/RX 正常; 再断开短接,把飞控接上,看到 MAVLink 乱码(以 0xFD/0xFE 开头的十六进制流)= 线通、波特率对。

④ 示例

最小可用程序(C 语言,termios 原生调用,编译 gcc uart_demo.c -o uart_demo):

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <termios.h>

int main(void) {
    int fd = open("/dev/ttyAMA0", O_RDWR | O_NOCTTY | O_NONBLOCK);
    if (fd < 0) { perror("打开串口失败"); return 1; }

    struct termios tio;
    tcgetattr(fd, &tio);
    cfmakeraw(&tio);                      /* 原始模式: 不做任何转换 */
    cfsetispeed(&tio, B115200);           /* 波特率 115200 */
    cfsetospeed(&tio, B115200);
    tio.c_cflag |= CREAD | CLOCAL;        /* 使能接收 */
    tio.c_cc[VMIN] = 0;                   /* 非阻塞读 */
    tio.c_cc[VTIME] = 5;                  /* 0.5 秒超时 */
    tcsetattr(fd, TCSANOW, &tio);

    char buf[256];
    for (int i = 0; i < 10; i++) {
        int n = write(fd, "ping\n", 5);   /* 发送 */
        printf("发出 %d 字节\n", n);
        usleep(500000);
        n = read(fd, buf, sizeof(buf));   /* 接收 */
        if (n > 0) { buf[n] = 0; printf("收到 %d 字节: %s\n", n, buf); }
    }
    close(fd);
    return 0;
}

等价的 Python(第 6 节还有更多):

4. 连接飞控(MAVLink)

市面飞控(Pixhawk / ArduPilot / PX4 / Auterion 等)对外的标准协议是 MAVLink—— 一种二进制帧协议:每帧以 0xFD(v2)或 0xFE(v1)开头,内含系统号、消息号、数据与 CRC 校验。 你不需要手写协议:《串口监控工具》的「飞控 MAVLink」页已经内置解析。

方式 A:USB 直连(你现在的方式,推荐调试期用)

飞控 USB 口插到 Jetson → 自动出现 /dev/ttyACM0 → 工具「飞控 MAVLink」页选它 → 115200 → 连接。 USB 虚拟串口不挑波特率(设多少都行),免接线、免释放、带电源,是最安全的验证方式。

方式 B:40-pin UART 接线(装机用)

① 针脚定义

Pixhawk 系飞控的 TELEM 口一般是 6-pin JST-GH 座(Pixhawk 连接器标准 DS-009): 脚1=5V(Vt)、脚2=TX、脚3=RX、脚4=CTS、脚5=RTS、脚6=GND。 不同飞控可能不同,接线前务必翻你的飞控手册或用万用表确认!

Jetson 40-pin↔飞控 TELEM(JST-GH 6pin)线色惯例说明
脚 8(UART1_TX)→脚 3(RX)黄/橙必须交叉!
脚 10(UART1_RX)←脚 2(TX)绿
脚 6(GND)—脚 6(GND)黑不共地 = 乱码/烧口
不接脚 1(5V)红除非明确要 Jetson 给飞控供电(拉载请评估电流)
不接脚 4/5(CTS/RTS)—硬件流控,两端都没开流控就不接
⚠️ 三条铁律: ① TX 接 RX、RX 接 TX(直连 = 永远没数据);② GND 必须共地; ③ Jetson 串口是 3.3V 电平,飞控 TELEM 也是 3.3V——恰好匹配,但别接到飞控的 5V 电平口(如某些 GPS 口)。

② 一般用法

  1. 释放 40-pin 串口(见第 3 节),重启。
  2. 飞控侧开 MAVLink:找一个空闲 TELEM/UART 口配置为 MAVLink——
    • PX4:参数 MAV_1_CONFIG 指到该口(如 TELEM2),SER_TEL2_BAUD=57600 或 115200,MAV_1_MODE=Normal(外部电脑用 Onboard 亦可);
    • ArduPilot:SERIAL2_PROTOCOL=2(MAVLink2),SERIAL2_BAUD=57 或 115。
  3. Jetson 侧:工具「飞控 MAVLink」页 → ttyAMA0 → 选与飞控一致的波特率(拿不准就点【自动嗅探波特率】)→ 连接。
  4. 看到心跳后即可切模式/解锁/上锁(解锁有双重确认),STATUSTEXT 窗口会滚动显示飞控日志。

5. 其他串口专题

5.1 /dev/ttyTCU0 —— 调试串口(Tegra Combined UART)

要点内容
① 定义SoC 内部调试口,固定 115200 8N1,永远输出内核/启动日志(console=ttyTCU0),板上没有外露排针
② 用法一般不要动。想看启动日志:接 USB 转串口线到载板调试点,或 sudo cat /dev/ttyTCU0;改造引导/排查不开机时它就是生命线
③ 原文链接Forecr · Jetson Orin NX Serial Console 说明; NVIDIA UART 指南
④ 示例sudo cat /dev/ttyTCU0 → 能看到实时内核日志;插上 USB 线连 PC 时,PC 端打开 115200 终端即可看到完整启动过程

5.2 /dev/ttyTHS0 / ttyTHS3 / ttyTHS4 —— Tegra 板载高速 UART

要点内容
① 定义Tegra SoC 的硬件 UART(UARTA/C/D),3.3V 电平。但本载板上:ttyTHS0 走 M.2 Key E 槽(1.8V,给 WiFi/BT 模组)、ttyTHS3/4 未布线到任何外露接口
② 用法没有排针可接,主要价值:① 自环/协议学习(两个口互接?——不行,只有软件层可见);② 配合 USB 转串口模块飞线测试点(高级);③ 在虚拟终端/pty 上做开发调试
③ 原文链接NVIDIA UART 指南; 载板规格书(M.2 Key E 节)
④ 示例stty -F /dev/ttyTHS0 115200 raw -echo && timeout 2 cat /dev/ttyTHS0 | xxd —— 能正常打开、无数据,说明设备树配置正常(载板没接东西,属预期)

5.3 /dev/ttyACM* 与 /dev/ttyUSB* —— USB 虚拟串口

要点内容
① 定义USB 设备虚拟出来的串口:ttyACM*=USB CDC-ACM 类设备(你的 PX4 飞控、Arduino 等);ttyUSB*=FT232/CP210x/CH340 等 USB 转串口芯片
② 用法即插即用,dialout 组免 sudo;热插拔后编号可能变化,用 ls -l /dev/serial/by-id/ 拿唯一路径写死到程序里
③ 原文链接kernel.org · usb-serial 文档
④ 示例ls -l /dev/serial/by-id/ → 你会看到 usb-Auterion_PX4_FMU_v6C.x_…-if00 → ../../ttyACM0, 在 MAVLink 页/你的程序里用这个 by-id 路径就不会认错设备

6.3 Python(termios,零依赖)

#!/usr/bin/env python3
"""串口透传: 把 ttyAMA0 收到的数据打印成 HEX+ASCII, 5 秒后退出"""
import os, termios, time, select

DEV = "/dev/ttyAMA0"
fd = os.open(DEV, os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)
a = termios.tcgetattr(fd)
a[0] = a[1] = 0                                  # iflag/oflag 清零
a[3] &= ~(termios.ECHO | termios.ICANON | termios.ISIG | termios.IEXTEN)
a[4] = a[5] = termios.B57600                     # ← 波特率
termios.tcsetattr(fd, termios.TCSANOW, a)

t0 = time.time()
while time.time() - t0 < 5:
    r, _, _ = select.select([fd], [], [], 0.2)
    if r:
        data = os.read(fd, 4096)
        print(time.strftime("%H:%M:%S"),
              "HEX:", data.hex(" ").upper(),
              "| ASCII:", "".join(chr(b) if 32 <= b < 127 else "." for b in data))
os.close(fd)

6.4 手工解析 MAVLink 帧(理解协议用)

#!/usr/bin/env python3
"""MAVLink v2 帧结构速查:
   FD | LEN | INC | CMP | SEQ | SYS | CMP | MSGID(3B) | PAYLOAD(LEN) | CRC(2B) [,签名13B]
   CRC 算法: 初值 0xFFFF + 反射多项式 0x8408(俗称 CRC16/X.25),
   但注意【最终不做 0xFFFF 异或】——这是 MAVLink 私有变体,网上大多数 X.25 代码会多异或一次!
   校验范围 = LEN..MSGID 头部 + PAYLOAD + 每消息的 CRC_EXTRA 字节"""
def mavlink_crc(data, crc=0xFFFF):
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0x8408 if crc & 1 else crc >> 1
    return crc

# 例: HEARTBEAT(消息号0) 的 CRC_EXTRA = 50
