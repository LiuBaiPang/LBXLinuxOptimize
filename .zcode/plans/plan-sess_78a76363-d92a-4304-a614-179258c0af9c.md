# 5-USB监控面板 实施方案

## Context
Jetson Orin NX 经常因 USB 供电不足导致卡顿/设备掉线（内核日志已证实：鼠标口被 hub 禁用(EMI)、两台 RealSense 掉线）。需要一个**原生 Linux GUI 应用**实时查看：所有 USB 设备信息、速率、功耗、实时传输吞吐、USB 摄像头实时画面、供电传感器电流电压。

## 新目录：`5-USB监控-linux-arm64-JetsonOrinNX/`
照 1/2 号工具模板（tkinter 深色主题 + sudo -S 提权 + 队列喂 GUI），文件：

| 文件 | 内容 |
|---|---|
| `usb_monitor.py` | 主程序（python3 + tkinter，无新依赖） |
| `usbmon_helper.py` | root 深度监控助手：读 usbmon 统计每设备收发字节/速率，JSON 行输出到 stdout |
| `actions_usb.sh` | root 动作脚本：INA3221 读取权限修复(tmpfiles.d)、启用 jtop.service、一键禁用/恢复全部 USB 自动休眠、切换 nvpmodel |
| `启动USB监控.sh` | 启动器（cd 到目录 exec python3） |
| `USB监控工具.desktop` | 目录内双击启动，Name=USB监控工具，Icon=media-removable，Exec 绝对路径 |
| `使用说明.md` | 中文文档（照 3/4 号的结构） |

另在根 `README.md` 的目录简介列表加一行。

## 面板功能（单窗口深色主题，左树右卡片）
1. **设备树**（左）：root hub→hub→设备 层级，每项显示 名称 + 速率徽章(480M/5G) + 请求电流(mA)，1s 自动刷新，拔插即时感知
2. **设备详情**（右上）：VID:PID、厂商/产品/序列号、USB 版本、**协商速率 vs 最大速率**（降速检测）、bMaxPower(请求mA)、runtime_status(active/suspended) 及休眠抖动计数、power/control(auto/on)、授权状态、各接口驱动
3. **供电健康**：INA3221 各通道 电压V/电流A/功率W（优先走 jtop 库，jsz 在 jtop 组；不可用则提示一键修复走 actions_usb.sh 的 tmpfiles.d 免root化）+ 5V 欠压告警(<4.75V 红) + 每 hub Σ请求电流 vs 端口预算 + nvpmodel 模式显示/切换
4. **实时传输**：USB 存储类设备走 /proc/diskstats 显示读写 MB/s；「深度模式」开关 = sudo 启动 usbmon_helper.py 流式解析 usbmon，给出**每设备 RX/TX 速率**（拒绝 sudo 则灰显）
5. **摄像头实时画面**：枚举 /dev/video*（12个 RealSense 节点）下拉选择，OpenCV 抓帧→tk.PhotoImage 预览，显示 FPS/分辨率/估算吞吐/掉帧计数
6. **USB 事件日志**：tail /var/log/kern.log（adm 组可读）过滤 usb 关键词，掉线/重置/over-current/EMI disabled 分级着色
7. **快捷操作**：禁用USB自动休眠(power/control=on)/恢复、重新枚举指定设备(unbind/bind)、INA 权限修复按钮；密码用 1/2 号工具同款 GUI 密码框+内存缓存，不落盘
8. 冒烟钩子 `AAAFIX_SMOKE=1`：采一轮快照打 JSON 退出，不开 GUI

## 线程模型
sysfs 轮询线程(1s) + kern.log tail 线程 + 摄像头线程 + 可选 usbmon 助手进程 → queue → GUI `after()` 消费（沿用 1/2 号模式）。

## 验证
1. `AAAFIX_SMOKE=1 ./启动USB监控.sh` 输出 9 设备快照 JSON 正确
2. 打开 GUI：树与 `lsusb` 一致、RealSense 720mA 显示正确、点选设备详情完整
3. 摄像头预览起流、FPS 正常；拔插 U 盘树即时更新
4. 不给 sudo：功能正常降级灰显；给 sudo：深度模式速率数字合理
5. 事件日志能看到历史 RealSense disconnect 记录
6. auto-sync 会自动 commit/push 新目录（无敏感文件，密码不落盘）
