# 6 号工具:串口监控/控制/资料手册(Jetson Orin NX ↔ PX4 飞控)

## 背景

你在 Jetson 上看到多个串口但不会用,想接飞控。探索发现:

- **本机实际串口**:`ttyTHS0/3/4`(空闲,dialout 组可读写)、`ttyAMA0`(**40-pin 排针 8/10 脚**,当前被内核 console + 登录终端占用)、`ttyTCU0`(调试口,115200)、`ttyACM0`(**你已插着一台 Auterion PX4 FMU v6C 飞控走 USB,免 sudo 直接可用**)、`ttyGS0`(USB 虚拟口)、`ttyS0-3`(8250 遗留探测口,无真实硬件)
- **gcc/ncurses 环境**:纯 Python tkinter 方案无需任何依赖安装
- 仓库规范:新目录 `6-串口监控-linux-arm64-JetsonOrinNX/`,完全仿照 `5-USB监控-linux-arm64-JetsonOrinNX/`(tkinter 深色 GUI + actions 脚本 + desktop 启动器 + 使用说明)

## 新建文件(全部在 `6-串口监控-linux-arm64-JetsonOrinNX/`)

### 1. `serial_monitor.py` — 主程序(tkinter 深色 GUI,4 个标签页)

复用 5 号模板:`C_BG="#14181f"` 系配色、`HERE` 定位、`AAAFIX_SMOKE=1` 冒烟测试、自动补 `DISPLAY=:0`、中文注释。

- **「串口总览」页**(默认,免 root):自动扫描 `/dev` 下 `ttyTHS* ttyAMA0 ttyTCU0 ttyS* ttyACM* ttyUSB* ttyGS0`,表格列出:设备名、硬件来源(sysfs 实链如 `3100000.serial`)、类型(板载UART/USB/调试口/遗留探测/虚拟)、**占用状态**(flock 探测 + 占用进程名)、当前用户可否读写、RX/TX 字节计数与速率曲线(canvas sparkline)。选中某口可点「实时预览」开 hex/ASCII 分栏窗口——弹窗先警告"预览会消费该口数据,飞控在用的口勿预览";被 getty 占用的口显示原因与解决按钮。
- **「串口终端」页**(控制程序):端口+波特率(1200~4M 常用列表)+数据位/停止位/校验/流控,连接/断开;接收区(hex/ASCII 切换、时间戳、暂停滚动、保存文件);发送区(文本/HEX、回车发 CR/LF/CRLF/无、快捷短语按钮、定时循环发送)。读线程用 `select()` → queue → UI,不冻结界面。
- **「飞控 MAVLink」页**:选口连波特率(常见 115200/57600,可自动嗅探 0xFD/0xFE 帧头),连上后实时显示:心跳频率、sysid/compid、机型、固件(ArduPilot/PX4 自动识别)、**飞行模式、解锁状态、电压/电流/电量、姿态 roll/pitch/yaw、高度、GPS 卫星数/定位**、消息速率表、STATUSTEXT 飞控日志窗。发送区:请求数据流/设频率、模式下拉(按固件自动切换 PX4/ArduPilot 模式表)、**解锁/上锁红色大按钮**(弹窗+输入"ARM"二次确认)、每条指令记日志。
- **「资料」页**:40-pin 关键引脚简表 + 「打开完整手册」按钮(`webbrowser.open` 本地 HTML)。

### 2. `mavlink_min.py` — 纯 Python 标准库 MAVLink 解析/构造器

支持 v1(0xFE)与 v2(0xFD)帧,CRC-16-X25 + CRC_EXTRA 芯验;HEARTBEAT、SYS_STATUS、ATTITUDE、GLOBAL_POSITION_INT、GPS_RAW_INT、COMMAND_LONG、COMMAND_ACK、STATUSTEXT、REQUEST_DATA_STREAM、SET_MODE 等常用消息;流式缓冲解析 + 线程安全队列。**不依赖 pymavlink**,手写约 300 行。ArduPilot 与 PX4 两套 custom_mode→模式名映射。

### 3. `serial_actions.sh` — root 动作脚本(仿 `actions_usb.sh`:子命令分发、幂等、`set -uo pipefail`)

- `free-40pin`:释放 40-pin UART 给飞控用 —— `systemctl disable --now serial-getty@ttyAMA0`、备份并修改 `/boot/extlinux/extlinux.conf` 去掉 `console=ttyAMA0,115200`、写 udev 规则 `/etc/udev/rules.d/99-aaafix-uart.rules`(ttyAMA0 → dialout 组),提示需重启生效
- `restore-40pin`:完整还原以上全部(有备份恢复)
- `status`:报告 console= 参数、getty 状态、规则在位情况
- GUI 对应位置提供「一键释放 40-pin 串口」按钮,sudo -S 调用、密码仅内存缓存(仿 5 号)

### 4. `资料手册.html` — 独立离线中文手册(单文件,浏览器打开)

每个主题固定按你要求的结构:**① 针脚定义 → ② 一般用法 → ③ 原文链接(可点击)→ ④ 示例**

- **40-pin 排针全引脚彩色图**(CSS 画双排针图)+ 完整定义表(电源/GND/I2C/UART/SPI/CAN/I2S),实现时以本机 `/opt/nvidia/jetson-io` 的 pinmux 数据与 NVIDIA 官方文档核对
- **串口专题**(每个设备一节):ttyAMA0(重点:8=TX、10=RX、6/14=GND、3.3V 电平严禁 5V)、ttyTHS0/3/4、ttyTCU0、ttyACM0;含"console 占用如何释放"教程
- **飞控接线教程**:40-pin UART ↔ PX4 TELEM 口接线表(**TX→RX 交叉、GND 共地、不接电源脚**)、波特率与 PX4 参数(SER_TEL2_BAUD)、USB 直连说明(你现在这台就是)、MAVLink 入门
- **示例**:stty 命令行、C termios 最小程序、Python 读写、MAVLink 抓帧,各带注释
- 原文链接:NVIDIA 官方文档、elinux.org、PX4/ArduPilot 文档、jetsonhacks 引脚图等
- 故障排查表(乱码→波特率/共地、无数据→TX/RX 交叉、口被占用→free-40pin…)

## 关键技术决策

- 监控默认**只读元数据**(sysfs/proc,不开口),预览需显式点击并警告——绝不悄悄消费飞控数据
- MAVLink 用纯标准库实现,零第三方依赖;连不上时引导回串口终端页排查
- 权限:总览/终端/MAVLink 全部免 root(仅 ttyAMA0/ttyTCU0 需先 free-40pin)

## 验证

1. `AAAFIX_SMOKE=1 ./启动串口监控.sh` 冒烟测试(仿 5 号打 JSON 退出)
2. 总览页应列出上述全部真实端口,ttyACM0 识别为 PX4
3. **飞控页连 `ttyACM0@115200` 现场验证心跳/姿态/电量真实遥测**(你的飞控就插着)
4. 用 python `pty` 虚拟串口对自测终端页收发 + MAVLink 帧构造/解析自测
5. 浏览器打开手册检查排版、链接可点
6. `serial_actions.sh status` 前后对比;`free-40pin`/`restore-40pin` 需你确认后才执行(涉及重启)
7. autosync 15 秒内自动入库,无需手动 commit
