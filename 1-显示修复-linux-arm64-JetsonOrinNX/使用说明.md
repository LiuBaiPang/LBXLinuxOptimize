# 显示修复工具 —— 使用说明

## 解决什么问题

Jetson 物理 HDMI 接口的显示器完全没有输出，但 NoMachine 远程连接一切正常。

## 根因（本机已确诊）

`/etc/X11/xorg.conf.d/99-nvidia-tegra.conf` 里有一行 NVIDIA 原厂的强制配置：

```
Option "ConnectedMonitor" "DFP"
```

它让 NVIDIA 驱动**只认第一个数字输出口（DP-0）**，把 HDMI 口完全屏蔽：
X 服务器把整个画面都送到 DP-0（NoMachine 看到的就是这个画面），物理 HDMI 口从不点亮。

## 使用方法

1. 双击 `显示修复工具.desktop`（或 `启动显示修复.sh`，弹出提示选"运行"）
2. 程序启动后自动诊断，日志里会直接告诉你根因
3. 保持 **"自动检测(推荐)"** + **"跟随显示器(推荐)"**，点 **【应用配置】**
4. 输入你的登录密码 → 等待重启显示服务（画面黑几秒自动恢复）
5. 查看物理显示器，应该已经亮了

### 各个控件的作用

| 控件 | 作用 |
|---|---|
| 输出模式下拉框 | 自动检测=去掉屏蔽让系统自己认屏（首选）；强制HDMI/DP=手动指定输出口；HDMI+DP=双屏同显 |
| 分辨率下拉框 | 强制指定输出分辨率，一般保持"跟随显示器" |
| 开关1 应用后立即重启显示服务 | 配置改完马上生效（会闪断几秒） |
| 开关2 强制点亮 | 当 HDMI 热插拔检测坏了、系统认为"没插线"时，写入自定义刷新参数硬点亮 |
| 【立即点亮HDMI】 | 不改配置、不重启，直接用 xrandr 实时点亮（轻量尝试） |
| 【恢复NVIDIA原厂】 | 一键还原出厂配置，撤销所有修改 |

### 排查顺序

1. 【应用配置】自动检测 → 大概率直接修好（根因就是屏蔽行）
2. 没好 → 模式选"强制HDMI输出"再应用
3. 还没好 → 开"强制点亮"开关再应用一次
4. 检查显示器端：输入源是否选对 HDMI、换一根 HDMI 线

## 文件结构

- `显示修复工具.desktop` —— 双击启动的入口
- `启动显示修复.sh` —— 备用启动方式（终端运行）
- `display_fix.py` —— 图形界面（Python/tkinter）
- `actions_display.sh` —— 实际修改系统配置的 root 脚本（由界面自动调用）
- 修改前自动备份：`/etc/X11/xorg.conf.d/99-nvidia-tegra.conf.aaafix.bak`
