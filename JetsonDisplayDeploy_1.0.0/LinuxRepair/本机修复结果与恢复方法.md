# 本机显示修复结果与恢复方法

日期：2026-11-01。对象：这台 Jetson Orin NX、R35.6.4、HIV QHD 显示器。

## 已确认结果

用户现场确认至少一轮：物理屏正常 → 拔掉视频线后 NoMachine 继续更新且可操作 → 插回后物理屏恢复。

SSH 最终验证：状态 confirmed，方案 test-edid，配置校验匹配，自动恢复定时器已停止。本配置已经写入磁盘，不会按180秒期限撤销。

原来的 `ConnectedMonitor "DFP"` 实际选中无EDID的 DFP-0。仅取消它能够恢复真实物理显示，但无屏时远程卡住。最终方案固定正确的 DFP-1 并使用从实际显示器读取且校验通过的256字节EDID。

## 最终配置

文件：`/etc/X11/xorg.conf.d/99-nvidia-tegra.conf`。

```text
Section "Device"
    Identifier "Tegra GPU"
    Driver "nvidia"
    Option "AllowEmptyInitialConfiguration" "true"
# LinuxRepair auto-detect test:     Option "ConnectedMonitor" "DFP"
    Option "ConnectedMonitor" "DFP-1"
    Option "CustomEDID" "DFP-1:/var/lib/linux-repair-display/edid-b8707baf4ed784fe123e318c5861ee80f1009c8801f03d03b0825c993776774f.bin"
EndSection
```

其中注释掉的旧 DFP 行不生效。EDID 文件已经保存在 Jetson 上的 root 管理目录，不依赖用户程序文件夹。不要删除它，否则会失去已测试的 EDID 来源。通用ZIP不附带该显示器的专用EDID，其他电脑应重新采集。

## 查看状态（只读）

```bash
python3 /home/jsz/AAAFIXsystem/LinuxRepair/root_helper.py status
```

应看到 confirmed 和 test-edid。泛称 connected 是强制固定后的预期值，不能用来判断视频线现在是否真实插着。

## 如需退回自动检测

先保存桌面工作、保留 SSH，再执行：

```bash
sudo python3 /home/jsz/AAAFIXsystem/LinuxRepair/root_helper.py restore
```

这会恢复本轮 EDID 测试前的自动检测配置并重启 GDM，关闭桌面程序、断开 NoMachine。它不是恢复最早错误的 DFP 配置。自动检测下本机已知现象是物理屏正常，但拔线后远程可能黑屏，因此只有需要撤销固定方案时才执行。

## 尚未验证与维护

尚未验证无屏冷启动、更换显示器、长时间连续运行及其他分辨率。固定EDID的模式来自当前显示器，更换显示器时先检查兼容性；不能照抄到其他载板。没有安装弹窗提示的dGPU驱动，没有修改设备树、内核、网络或磁盘。

该 GPU Setup 弹窗选择“否”。它是工厂自启动脚本，不是修复程序发起的；本次未删除自启动文件。

本次SSH公钥注释为 `codex-jetson-display-20261101`，由用户手动加入 `~/.ssh/authorized_keys`。如后续不需要此电脑继续SSH维护，可备份该文件后只移除带此注释的那一行，不要删除其他公钥。ZIP内不含SSH私钥或密码。
